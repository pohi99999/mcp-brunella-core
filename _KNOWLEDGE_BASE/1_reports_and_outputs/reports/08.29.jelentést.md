

## **Kutató Ügynök Jelentése: Projekt "Multiplier"**

Dátum: 2025\. augusztus 29\.  
Jelentés Azonosító: KP-20250829-MULTIPLIER  
Státusz: Folyamatban  
Ez a jelentés a "Multiplier" projekt első fázisának kutatási eredményeit tartalmazza. A cél olyan alapvető technikák és protokollok felkutatása, amelyek a teljes ügynöki rendszer (kódnevén "Brunella") megbízhatóságát és koordinációs képességét növelik. A kutatás két fő irány mentén zajlott.

---

### **1\. Irány: Az "Ügynök Alkotmány" és Megbízhatóság Mesterfogásai**

Ezen a területen az ügynökök belső működését, gondolkodási folyamatait és megbízhatóságát célzó technikákat vizsgáltam. A cél, hogy minden egyes ügynök önállóan is robusztusabb és kiszámíthatóbb legyen.

#### **1.1. Technika: ReAct Keretrendszer (Reasoning \+ Acting)**

* **Forrás:** [Prompting Guide \- ReAct](https://www.promptingguide.ai/techniques/react)  
* **Rövid Leírás:** A ReAct egy olyan promptolási technika, amely arra ösztönzi a nyelvi modelleket, hogy a feladatmegoldás során váltogassanak a **gondolkodás** (a helyzet elemzése, terv készítése) és a **cselekvés** (eszközök, pl. keresés használata) között. A modell egy Thought, Action, Observation (Gondolat, Cselekvés, Megfigyelés) ciklust követ, amellyel transzparensen dokumentálja a teljes folyamatot a végső válasz megadása előtt.  
* **Potenciális Alkalmazás:** A Brunella rendszer összes ügynökének alapvető működési elvébe integrálható. Különösen a Tervező és a Végrehajtó ügynökök esetében növelné drasztikusan a komplex feladatok megoldásának sikerességét és az utólagos hibakeresést.  
* **Nyers Adat (Zero-Shot Prompt Példa):**  
  Oldd meg a feladatot a ReAct (Reasoning and Acting) megközelítéssel. Minden lépésnél kövesd a formátumot:

  Thought: Értékeld a helyzetet és a következő lépést.  
  Action: \[A végrehajtandó cselekvés, pl. Search\[lekérdezés\]\]  
  Observation: \[A cselekvés eredménye\]

  Folytasd ezt a ciklust, amíg meg nem oldod a problémát, majd add meg a végső választ.

  Final Answer: \[A végső válasz\]

#### **1.2. Technika: Belső Monológ / Gondolkodási Puffer (Internal Monologue / Scratchpad)**

* **Forrás:** [Relevance AI \- Scratchpad Prompting](https://relevanceai.com/prompt-engineering/use-scratchpad-prompting-to-improve-ai-interactions)  
* **Rövid Leírás:** Ez a technika arra utasítja az ügynököt, hogy a végső, felhasználónak szánt válasz előtt egy dedikált blokkban (pl. \<thought\> vagy \<scratchpad\>) vezesse le a teljes gondolatmenetét. Ez magában foglalja a probléma elemzését, a lépésekre bontást, a lehetséges zsákutcák mérlegelését és a döntési logikát. Ez a "hangos gondolkodás" lehetővé teszi az önkorrekciót.  
* **Potenciális Alkalmazás:** Minden ügynök alapvető "alkotmányába" beépítendő. Kényszeríti a strukturált gondolkodást, és a logok elemzésével pontosan láthatóvá teszi, hol siklott félre egy-egy folyamat. Brunella (a menedzser ügynök) számára elengedhetetlen a delegálási döntések előkészítéséhez.  
* **Nyers Adat:**  
  A végső válaszod előtt a \<thought\> tagek között vezesd le a teljes gondolkodási folyamatodat.  
  1\.  Elemezd a felhasználói kérést és a célt.  
  2\.  Hozz létre egy lépésről-lépésre haladó tervet.  
  3\.  Hajtsd végre a tervet, szükség esetén használj eszközöket.  
  4\.  Kritikusan értékeld az eredményeket, és ellenőrizd, hogy a cél teljesült-e.  
  5\.  Ezután fogalmazd meg a végső, tiszta választ a felhasználó számára.

  Final Answer:  
  ... csak a végső, letisztázott válasz ...

#### **1.3. Technika: Megbízható JSON Kimenet Kikényszerítése**

* **Forrás:** [Dev.to \- Crafting Structured {JSON} Responses](https://dev.to/rishabdugar/crafting-structured-json-responses-ensuring-consistent-output-from-any-llm-l9h)  
* **Rövid Leírás:** Az ügynökök közötti megbízható kommunikációhoz elengedhetetlen a strukturált adatformátum, mint a JSON. Ezt több rétegű technikával lehet kikényszeríteni:  
  1. **JSON Séma Megadása:** A promptban pontosan leírjuk a várt JSON struktúrát, a kulcsokat és az adattípusokat (pl. Pydantic vagy JSON Schema formátumban).  
  2. **Példák:** Egy-két "few-shot" példa a promptban, ami bemutatja a helyesen formázott kimenetet.  
  3. **Válasz Előre Kitöltése:** A prompt végén az asszisztens válaszát elkezdjük a nyitó { karakterrel, ezzel "rávezetve" a modellt a JSON generálására.  
* **Potenciális Alkalmazás:** Kritikus a Brunella és az alárendelt ügynökök közötti kommunikációban. A feladatok delegálása és a jelentések fogadása szigorúan strukturált JSON üzeneteken keresztül történhet, minimalizálva a félreértéseket.  
* **Nyers Adat:**  
  Feladat: Bontsd le a felhasználó kérését egy "Tervező" és egy "Kódoló" ügynök számára. A válaszod KIZÁRÓLAG egy érvényes JSON objektum legyen, ami megfelel a következő sémának:  
  {  
    "planner\_task": "string",  
    "coder\_task": "string"  
  }

  Felhasználói kérés: "Készíts egy Python szkriptet, ami letölti a napi időjárás-jelentést."

  Asszisztens válasza:  
  {

### **2\. Irány: Koordinációs Protokollok és Kommunikáció (Brunella Optimalizálása)**

Ez az irány a több ügynökből álló rendszer hatékony és hibatűrő együttműködésére fókuszál.

#### **2.1. Technika: Menedzser-Végrehajtó (Supervisor-Worker) Delegálási Minta**

* **Forrás:** [FlowiseAI Docs \- Multi-Agents](https://docs.flowiseai.com/using-flowise/agentflowv1/multi-agents)  
* **Rövid Leírás:** Egy "Supervisor" (Menedzser) ügynök felelős a komplex feladatok lebontásáért és a megfelelő "Worker" (Végrehajtó) ügynöknek való delegálásért. A menedzser promptja tartalmazza az elérhető végrehajtók listáját és azok specializációját. A menedzser addig koordinál, amíg az összes részfeladat el nem készül, és a végső cél nem teljesül, amit a FINISH kulcsszóval jelez.  
* **Potenciális Alkalmazás:** Ez a minta tökéletesen illeszkedik a Brunella rendszer architektúrájához. Brunella lesz a "Supervisor", amely a feladatokat a specializált (pl. Kutató, Tervező, Kódoló) ügynököknek delegálja.  
* **Nyers Adat (Menedzser Prompt Részlet):**  
  Te vagy a Menedzser ügynök. A te felelősséged, hogy a komplex feladatokat részfeladatokra bontsd és delegáld a megfelelő végrehajtónak.  
  A rendelkezésedre álló csapat tagjai: {team\_members}

  A feladat akkor van kész, amikor a végső választ a "FINISH" kulcsszóval adod vissza. Ne feledd, egyszerre csak egy végrehajtóval kommunikálj\!

#### **2.2. Technika: Strukturált Kommunikáció JSON Sémával**

* **Forrás:** [LLUMO Blog \- Inter-Agent Protocols for AI](https://www.google.com/search?q=https://www.llumo.ai/blog/inter-agent-protocols-for-ai)  
* **Rövid Leírás:** A szabad szöveges üzenetek helyett az ügynökök közötti kommunikációt egy előre definiált, szigorú JSON séma alapján kell végezni. Minden üzenettípusnak (pl. task\_delegation, status\_report, error\_message) saját sémája van. Ez gépileg könnyen validálhatóvá és feldolgozhatóvá teszi az üzeneteket.  
* **Potenciális Alkalmazás:** Az ügynökök közötti teljes kommunikációs folyamatot (Brunella \-\> Végrehajtó, Végrehajtó \-\> Brunella) ezen protokoll alapján kell újratervezni. Drasztikusan növeli a megbízhatóságot.  
* **Nyers Adat (Példa Séma a Feladatdelegáláshoz):**  
  JSON  
  {  
    "$schema": "http://json-schema.org/draft-07/schema\#",  
    "title": "TaskDelegation",  
    "type": "object",  
    "properties": {  
      "task\_id": { "type": "string", "format": "uuid" },  
      "delegate\_to": { "type": "string", "enum": \["PlannerAgent", "CoderAgent"\] },  
      "instructions": { "type": "string" },  
      "context": { "type": "object" },  
      "deadline": { "type": "string", "format": "date-time" }  
    },  
    "required": \["task\_id", "delegate\_to", "instructions"\]  
  }

#### **2.3. Technika: Állapotkezelés (State Management)**

* **Forrás:** [McKinsey \- Seizing the agentic AI advantage](https://www.mckinsey.com/capabilities/quantumblack/our-insights/seizing-the-agentic-ai-advantage)  
* **Rövid Leírás:** Egy központi, megosztott "állapot" (state) objektum tárolja a projekt aktuális helyzetét, a részfeladatok státuszát, az ügynökök leterheltségét és az eredményeket. Az olyan keretrendszerek, mint a LangGraph, gráf-alapú állapotgépeket használnak a komplex, nem lineáris munkafolyamatok kezelésére, ahol a következő lépés az aktuális állapottól függ.  
* **Potenciális Alkalmazás:** Brunellának rendelkeznie kell egy központi állapotkezelő modullal, amely minden aktív projektről és ügynökről naprakész információt tárol. Ez a modul dönti el, hogy egy feladat sikeres lezárása után mi legyen a következő lépés, vagy hiba esetén hogyan kell eszkalálni a problémát.  
* **Nyers Adat (Példa Állapot Objektum):**  
  JSON  
  {  
    "project\_id": "proj\_123",  
    "overall\_status": "in\_progress",  
    "tasks": \[  
      { "task\_id": "task\_001", "status": "completed", "assigned\_to": "PlannerAgent", "result": "..." },  
      { "task\_id": "task\_002", "status": "in\_progress", "assigned\_to": "CoderAgent", "result": null }  
    \],  
    "agent\_load": {  
      "PlannerAgent": 0.2,  
      "CoderAgent": 0.8  
    }  
  }
